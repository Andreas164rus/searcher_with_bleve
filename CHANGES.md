# Изменения

## 2026-11-18 — События во время первичного обхода не теряются

**Что было сломано.** Сначала строился индекс, и только потом запускался watcher. Файл, изменённый в этом окне, оставался в индексе в старой версии: подписки ещё не было, а повторно его никто не читал.

**Что сделали.** Watcher подписывается на папки до `BuildInitialIndex` и складывает события в буфер. Воркеры в это время индекс не трогают, поэтому обход не затирает более новую запись. После обхода буфер применяется обычным debounce. Если обход упал, буфер не проигрывается.

**Файлы.** `internal/watcher/watcher.go`, `internal/watcher/watcher_test.go`, `internal/app/app.go`, `README.md`.

## 2026-11-18 — Переименование папки обновляет пути в индексе

**Что было сломано.** `Rename` папки удалял один ID, равный пути самой папки. Папка документом не является, поэтому файлы внутри оставались в индексе под старым именем. Событие `Create` новой папки только подписывало fsnotify и не читало файлы внутри.

**Что сделали.** Удаление и переименование снимают документ и все ID с этим префиксом: `old` и `old/a.txt`, но не `old2`. Появление папки ставит в очередь каждый поддерживаемый файл внутри, и воркеры индексируют их уже по новому пути.

**Файлы.** `internal/search/index.go`, `internal/service/service.go`, `internal/service/service_test.go`, `internal/watcher/watcher.go`, `internal/watcher/watcher_test.go`, `README.md`.

## 2026-11-18 — indexPath больше не удаляет чужой каталог

**Что было сломано.** При старте и при `POST /index/rebuild` папка `indexPath` удалялась через `RemoveAll` без проверки. Если в конфиге указать каталог проекта, `rootDir` или любой другой существующий путь, стиралось всё его содержимое, а не только индекс Bleve.

**Что сделали.** Папка удаляется только если её нет или это индекс Bleve: внутри лежит файл `index_meta.json`. Корень файловой системы, каталог с `go.mod` и каталог с `.git` не удаляются. В этих случаях операция возвращает ошибку, а файлы остаются на месте.

**Файлы.** `internal/search/index.go`, `internal/search/index_test.go`, `README.md`.

## 2026-11-18 — Файл больше лимита уходит из индекса

**Что было сломано.** Первичный обход не индексирует файл больше `maxFileSizeBytes`. Обновление такого файла тоже его не читало, но старый документ в Bleve оставался. Поиск продолжал находить текст версии, которая уже больше лимита.

**Что сделали.** Если при обновлении файл больше лимита, пропал или стал ссылкой, документ с этим путём удаляется из индекса. Повторное удаление отсутствующего документа статистику не портит.

**Файлы.** `internal/service/service.go`, `internal/service/service_test.go`, `README.md`.

## 2026-11-18 — Один файл обрабатывает один воркер

**Что было сломано.** Все воркеры читали одну общую очередь. Пока первый ещё читал файл, следующий flush мог положить тот же путь снова, и его забирал другой воркер. Две задачи одного файла шли параллельно. Более новое удаление могло закончиться раньше более старого обновления, и документ возвращался в индекс.

**Что сделали.** У каждого воркера своя очередь. Путь хешируется и всегда попадает в одну и ту же. Повторные задачи файла встают друг за другом и выполняются по порядку. Разные файлы по-прежнему идут параллельно. Суммарный буфер очередей остаётся `updateQueueSize`, каждому воркеру достаётся хотя бы одно место.

**Файлы.** `internal/watcher/watcher.go`, `README.md`.

## 2026-11-18 — Debounce не зависает, если события не прекращаются

**Что было сломано.** Каждое событие файловой системы заново запускало таймер на `debounceMs`. Пока события приходили чаще, чем раз в этот интервал, пауза тишины не наступала, `pending` не сбрасывался в очередь, и индекс не обновлялся. Игнорируемые пути и создание каталога тоже сбрасывали таймер, хотя в `pending` они не попадают.

**Что сделали.** Пауза тишины осталась: несколько событий одного сохранения по-прежнему схлопываются в одну задачу. Рядом запускается второй таймер `2 * debounceMs`. Новые события его не сбрасывают, поэтому накопленные пути уходят в очередь не позже этого срока, даже если поток событий не прекращается. Таймеры двигаются только когда событие реально кладёт задачу в `pending`.

**Файлы.** `internal/watcher/watcher.go`, `README.md`.

## 2026-11-13 — Rebuild больше не ломает индекс после Close

**Что было сломано.** `POST /index/rebuild` сначала закрывал Bleve, потом сразу вызывал `Recreate`: удаление папки и создание индекса заново. После `Close()` файлы индекса (`root.bolt`, `.zap`) ещё заняты, поэтому `RemoveAll` падал, а `bleve.New` отвечал `cannot create new index, path already exists`. Индекс к этому моменту уже был закрыт, и поиск отвечал «Индекс закрыт».

**Что сделали.** Новый индекс собирается в соседней папке `indexPath + ".rebuild"`. Старый закрываем только после успешного скана. Папку удаляем несколькими попытками. Если удалить не получилось, старый индекс открываем обратно. Счётчики документов копируем в заново открытый индекс, потому что они живут в памяти.

**Файлы.** `internal/search/index.go`, `internal/service/service.go`, `internal/service/service_test.go`.
